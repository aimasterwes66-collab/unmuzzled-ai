## 0. How agents must use this workbook

1. Read `MASTER-AGENT-COORDINATION-DIRECTIVE.md` first. Keep current authorized work going; this workbook does not grant permission for disruptive changes.
2. Treat the ten ontology domains and 150 subsection prompts below as the *coverage map*. Fill the ten response fields for each subsection. A response may be `Unknown`, `Not applicable` with a reason, or a concise list with links and evidence. Never pad sections to reach an arbitrary number of installed tools.
3. Answer all 100 questions in Section C. Specialists answer their own areas; the coordinator merges answers, identifies disagreements, and requests owner decisions when necessary.
4. Use *read-only inventory* before suggesting bulk file operations. Do not rename, move, delete, deduplicate, edit, upload, or reorganize corpus files without an explicitly approved change plan and recoverable backup.
5. Do not paste credentials, private raw content, tokens, or secrets. A non-secret config path, redacted excerpt, hash, log reference, test command, or commit ID may be used as evidence.
6. Work in separate agent contributions or branches. Do not have multiple agents overwrite this workbook concurrently. Preserve the two input files; keep dated revisions, diffs, and a decision log.
7. Maintain remote-first heavy computation: local iMac handles control and bounded lightweight work; large-model inference and GPU-heavy media tasks use authorized remote endpoints unless the owner approves another path.
8. For every claim use one of: `Verified existing`, `Reported existing, unverified`, `In progress`, `Planned`, `Proposed`, `Absent`, `Unknown`, or `Not applicable`. Distinguish what has been tested from what was merely described.
9. If a source conflicts with another, retain both references and record the conflict. Do not quietly merge incompatible requirements, delete history, or select an arbitrary winner.
10. Final deliverables from this discovery round: completed coverage map, answered questionnaire, evidence index, unresolved decision register, and a non-destructive, dependency-ordered implementation plan for owner approval.

### Response convention for every ontology subsection

For each subsection, the numbered entries are ten required **response slots**, not ten assertions that components exist. Fill each slot with precise details, `Unknown`, or `N/A` and why. In lists of real components, add as many or as few as evidence warrants.

`Evidence reference` format: local path or repository URL + revision/mtime + relevant heading/line or command/test result (redact sensitive material). Do not manufacture line numbers.
